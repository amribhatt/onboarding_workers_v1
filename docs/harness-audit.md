# Harness audit: the nine things a complete agent harness does, and the seven ways a loop stops

Audited 2026-10-11 against the code in this repo (read, and the named tests run). A thing that cannot be pointed to is
a gap, not a simplification. Grades: **met** (code and a test that fails if it breaks), **partly** (the code exists but
a named part is missing or only convention), **not met**.

The loop itself is Deep Agents' (`create_deep_agent` in `agent.build_agent`: call the model, read the reply, run its
tool calls, repeat until a reply has no tool call). It is a library; this harness is what is built around it.

## 2. The stop reasons

One typed list (`stops.Stop`), one function (`stops.handle`): audit `run.stopped` first (action, reason, trace id, the
facts), then the fixed message, and `resumable` / `needs_human`. `agent._run` is the single caller around
`agent.invoke`; `agent.start` and `agent.decide` both go through it. A defined stop is returned in the agent's own
result shape with `result["stop"]` and the message as the last agent line; the thread's checkpoint is untouched, so
the next human message continues from it. The service shows it as run status `error` with the message and keeps
`run.stop` (persisted in `run.json`); the CLI prints it as the agent's line. Before this change a spend cap raised
through `start`, a step backstop became a raw exception string, and a cut-off reply was treated as an answer.

| Stop | Code path | What the person sees | Audited | State |
|---|---|---|---|---|
| `end_turn` | reply has no tool call: `agent._run` after `invoke` returns without `__interrupt__` -> `stops.handle(END_TURN)` | the agent's last message | `model.call` (stop `end_turn`), `run.stopped` | kept; thread idle, next message continues |
| `tool_use` | reply has tool calls: `stops.classify` in `RunLimits.wrap_model_call`; the loop continues | tool activity in the transcript | `model.call` (stop `tool_use`, tool names), then each tool's own record and a `tool.span` with the same `trace_id` and `seconds` | kept |
| `max_tokens` | `finish_reason` / `stop_reason` of `length`, `max_tokens`: `RunLimits.wrap_model_call` retries once with `RETRY_NOTE`; a second cut raises `RunStopped(MAX_TOKENS)`. The cut-off reply is never returned to the graph. Role calls: `roles.RoleRunner.call` refuses a cut-off answer and repairs within its attempt limit | message: cut off twice, nothing was changed by it, ask for a smaller step | `model.truncated` (retry), then `run.stopped` | kept; the truncated reply is not in the state; needs a human message |
| `max_iterations_exceeded` | more than `ctx.limits.max_iterations` model calls in one request (`RunLimits`), the job call cap (`BudgetMeter` -> `BudgetExceeded` -> `stops.from_exception`), or `GraphRecursionError` | message naming the limit and the env var to raise | `budget.exceeded` (call cap only) then `run.stopped` | kept; the refused call never reached the model; needs a human |
| `timeout_exceeded` | wall clock over `ctx.limits.max_seconds` since the invocation began: checked before every model call and every tool call (`RunLimits._on_time`) | message naming `WORKER_BUDGET_SECONDS` | `run.stopped` | kept; the call that would have run did not; needs a human. A tool already running is not interrupted |
| `guardrail_intervened` | provider `content_filter` / refusal on a reply (`RunLimits`); a code refusal of an approval (`agent.decide`, `service.decide` on `GateRefused`) | message: a guardrail ended this step, nothing changed | `run.stopped` with the refusing findings; tool refusals inside the loop stay `<tool>.refused` / `.blocked` records returned to the model | kept; a refused approval leaves the run at its gate |
| `hook_stopped` | a harness hook halts the run: `stops.RunStopped(Stop.HOOK_STOPPED)` raised from a model callback or middleware, or `AuditError` at the model-call boundary (a span that cannot be written) | message: a check that must run before every call halted the run | `run.stopped` (if the log itself is down the message says the record is missing: `Outcome.audited` false) | kept; the reply that could not be recorded was not acted on |

An eighth member, `token_budget_exceeded` (the job token cap), is separate because it is not an iteration count; it
behaves like `max_iterations_exceeded`. A pause at a gate is not a stop reason: it is the checkpointed interrupt
(item 7).

## 3. What remains open

- No preemption of a running in-process tool (item 3, 5): the wall clock acts between calls.
- Cost is tokens; no currency cap (item 5).
- Prompt text per call is not stored; hashes only (item 1).
- No OpenTelemetry export (item 8); the audit file and `/metrics` are the sinks.
- The live model has never been scored on real traces (item 9).
- `hook_stopped` has no user-registered hooks: the hooks are the audit-before-effect check and the model callbacks. A
  hook registry would be a new mechanism with no caller today.
